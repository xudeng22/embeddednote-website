## 四、E6 尺寸页去掉 Product 结构化数据

**发现**:11/22 收到 Search Console 邮件,提示"产品摘要结构化数据问题":Product 缺少 `offers`、`review` 或 `aggregateRating`。

**问题**:32 个页面(16 尺寸 × 2 语言)都发 `Product`,但站上不公开价格——既拿不到富媒体结果,又被记为严重问题。

**改动**

```
改前  @type: Product(缺 offers)
改后  @type: ItemPage
        └ mainEntity: Thing
             └ additionalProperty: 7 条(尺寸、分辨率、像素、颜色、RAW4、RAW8、ppi)
```

参数一条未丢,只是换了载体。页面本质是"某块面板的技术参考",不是商品详情页。

**线上**

- https://embeddednote.com/en/e-paper/e6/13-3-inch/
- https://embeddednote.com/zh/e-paper/e6/13-3-inch/
- 全部尺寸:https://embeddednote.com/en/e-paper/e6/

**验证**:Product 页面 0 个,ItemPage 生效,全站 299 个 JSON-LD 块解析无错误。

**后续**:等公开价格区间后,可用 `AggregateOffer`(lowPrice/highPrice)重新加回 Product,那时才是真的产品摘要。

## 五、Cloudflare 的 HTML 边缘缓存

**发现**:11/20 分析流量时发现 `Cache-Control: public, max-age=0, s-maxage=600` 虽然正确,但响应头是 `cf-cache-status: DYNAMIC`——Cloudflare 默认不缓存 HTML,`s-maxage` 对"不允许缓存的响应"无效。

**问题**:过去一个月每次页面请求都回源到 Pages,504 占比 11.4%。

**改动**:新建 Cache Rule(账户 `3b762b2256dd2df1047078da4114f243`,zone `eecc67329ddb1899acdf4181c489d249`)

```yaml
名称:     Cache HTML at the edge, bypass /api
表达式:   not starts_with(http.request.uri.path, "/api/")
动作:     Eligible for cache
边缘 TTL: 600 秒(覆盖源站)
浏览器 TTL: 遵循源站
```

**配置位置**:https://dash.cloudflare.com/3b762b2256dd2df1047078da4114f243/embeddednote.com/caching/cache-rules

**验证**:同一 URL 连续请求两次,第二次 `cf-cache-status: HIT`,`Age: 2`。
