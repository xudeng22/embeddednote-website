残影看起来像软件 bug:上一帧还在,淡淡地压在新画面下面。所以第一反应往往是"再刷一次"——换个模式刷、把同一个缓冲区再写一遍。

这些做法都不可靠,因为残影不是没刷新的缓存,而是**没走完的颜料**。重写同样的像素不会让它移动,只有全刷波形(足够的时间、正确的电压序列)才能重置薄膜的状态。

## 残影在物理上是什么

电子纸的一个像素是一个装着黑白颜料微粒的腔体,颜料悬浮在流体里。控制器用电压波形驱动它们:一串脉冲,幅度和持续时间决定微粒往哪一端走。全刷会让每个像素经历多次翻转,最后停在一个明确定义的状态。

局刷把大部分过程跳过了。它只写变化的区域,用更短的波形、更少的翻转。没被写的像素保持原状——这正是它的价值:快,而且不会整屏闪一下。

代价是:一个像素的最终状态取决于它的**起点**。从黑推到白的像素,和从灰推到白的,结果略有不同。局刷次数多了,这些细微差异会累积成旧画面的残影。

## 三个输入,不是一个

| 输入 | 它改变什么 | 你能控制什么 |
| --- | --- | --- |
| 上一帧画面 | 每个像素要走多远 | 你显示什么内容、多久换一次 |
| 温度 | 颜料黏度与翻转速度 | 选哪张波形表,以及是否允许局刷 |
| 刷新历史 | 距上次全刷经过了多少次短波形 | 一个计数器,和一个预算 |

多数实现碰巧管住了第一个,忽略第二个,第三个根本没做。而第三个是最便宜的。

## 为什么"再刷一次"有时更糟

对同一区域再做一次局刷,等于把同一个短序列再走一遍。如果残留来自"翻转没走完",重复一次可能有用;如果残留来自电极上积累的电荷,重复同一个短波形会加深不平衡,而不是清除它。

可靠的操作不是重复,而是**全刷**——全刷序列本来就是为"把所有像素归一到确定状态"设计的。所以修复点应该在更新策略里,不在按钮回调里。

## 温度不是细节

冷的时候颜料走得慢。25 °C 下 300 ms 能完成的翻转,到 0 °C 可能完不成,屏上就会出现一个发灰、带残影的画面,看起来和软件 bug 一模一样。厂商按温度区间提供不同的波形表,控制器本来就应该选对那一张。

两个公开数据可以说明量级:E Ink 给 [Spectra 6](https://cn.eink.com/brand/detail/Spectra6) 模块(常简称 **E6**)标注的工作温度是 **0–50 °C**,给 [Marquee](https://cn.eink.com/brand/detail/marquee) 标注的是 **−20 到 65 °C**(翻转时间 5–7 秒)。这是品牌级参数,不是你那块屏的数据手册,但它说明一件事:工作温度是被明确规定的参数,忽略温度的驱动只在一个很窄的区间里是对的。

三个直接后果:

1. **选波形之前先读温度。** 如果驱动里写死了一张表,它只在一个温度区间内是对的。
2. **低于厂商给的下限就禁用局刷。** 局刷波形余量更小,低温下会安静地失败。
3. **不要自己编补偿曲线。** 波形表来自面板特性测试。自己猜一个缩放系数,20 °C 看着还行,−10 °C 可能直接伤屏。

如果产品要卖到寒冷地区,这是硬件需求,不是固件微调:面板、控制器、波形集三者都要覆盖那个温区。

## 真正能站住的更新策略

两个计数器,三个门。这里没有厂商相关的假设:

```c
/* 策略骨架,不是驱动 */
#define PARTIAL_BUDGET 20

static uint32_t partial_count = 0;
static int      last_mode = -1;

bool need_full_refresh(void)
{
    if (last_mode != MODE_FULL)              return true; /* 模式或波形变了 */
    if (partial_count >= PARTIAL_BUDGET)     return true; /* 预算用完       */
    if (panel_temp_c() < TEMP_MIN_PARTIAL)   return true; /* 温度太低       */
    return false;
}

void note_update(int mode)
{
    if (mode == MODE_FULL) partial_count = 0;
    else                   partial_count++;
    last_mode = mode;
}
```

预算值是唯一需要你拍板的数字,而它是产品决策。一分钟更新一次的桌面时钟,可以每小时全刷一次;一天更新四次的价格标签,可能根本不需要局刷。先保守一点——10 到 20 次局刷后强制全刷——再实测。

有两条规则比这个数字更重要:

- **换调色板、换旋转、换波形之后,必须先全刷。** 新模式的第一帧,不能和旧模式的最后一帧直接比较。
- **大面积纯色区域不要局刷。** 这种翻转对短波形要求最高,而且残留最明显。

## 怎么判断"可以接受"

残影是一条连续光谱,"没有残影"不是可测的验收标准。用固定序列 + 固定观察条件:

1. 显示帧 A(高对比:白底上一块大黑块),拍照。
2. 显示帧 B(几乎全白),在**同样的光源、距离、曝光**下拍照。
3. 再显示 A、再显示 B,重复十次。
4. 比较十张 B 里"原本是黑块"那块区域的亮度。

如果这块区域单调变亮,而且全刷之后也恢复不了,说明面板累积残留的速度比策略清除的快;如果全刷后能恢复,问题就在策略;如果怎么都恢复不了,面板已经产生了不可逆的定型,改固件也没用。

每张照片都要记录温度和波形版本。没有这两个数的残影报告,无法复现。

## 我们不知道的部分

我们没有针对任何具体型号测过"面板寿命与局刷次数"的关系,厂商也很少公开这条曲线。同样,某块屏在多少度以下开始不可靠,这个数字只能来自面板数据手册和你自己的低温测试。

能确定的是结构性的东西:残影依赖历史、依赖温度、依赖模式。任何忽略其中一项的实现,都会产出无法复现的 bug 报告。

## 策略带来的三个问题

### 显示一张全白画面放一会儿,能把残影清掉吗?

不能。白画面只是另一张图,用的还是留下残影的那套短波形。能把薄膜重置的只有全刷序列。如果觉得“白一下有用”,那是对比度变了、残影在白底上不那么显眼,面板并没有恢复。

### 每分钟更新一次的时钟,PARTIAL_BUDGET 该定多少?

一天 1,440 次更新。预算 20 就是每天 72 次全刷,每 20 分钟闪一下。预算 120 允许两小时一次强制全刷,于是“每小时全刷”先触发,一天 24 次。先定你能接受的一天闪几次,再反推预算。

### 残影是永久的,还是停更一段时间会自己淡掉?

看颜料被推到什么程度。翻转没走完留下的残留,全刷通常能清。电极上积累的电荷,或者长期在温区之外使用的面板,可能留下不可逆的定型,什么波形都救不回来。用文中那个十帧测试就能判断你遇到的是哪一种。
